## REGLAS GRABADAS (aprendidas)
- **(v6.60.0) `eol=lf` NO convierte en checkout.** Git vuelca el blob tal cual: blob CRLF → worktree CRLF. La normalización ocurre solo al LEER (filtro `clean`). De ahí el bucle: `status` compara worktree-normalizado contra blob-crudo y siempre da "modificado". Medido: los archivos "sucios" tenían mtime igual al segundo del `checkout` del reflog — los escribió git.
- **(v6.60.0) Cuatro herramientas NO limpian el fantasma CRLF** — medido 1×1: `git restore`, `git checkout -- <file>`, `git checkout -f <branch>`, `git stash push -- <files>`. Todas reescriben desde el mismo blob CRLF. **La vía que sí funciona es operar sobre REFS:** `git push origin <local>:<remota>` (ff en el servidor, sin filtro de EOL) y `git branch -f <rama> <hash>` (sin checkout). Destrabó un `merge --ff-only` que había abortado 4 veces.
- **(v6.60.0) `hash-object --no-filters` y `git status` pueden discrepar legítimamente.** Uno compara bytes crudos, el otro aplica `clean`. Ambas lecturas son correctas — miden cosas distintas. Diagnóstico concluyente: `git ls-files --eol` (`i/` vs `w/`) + `git diff --numstat` (insertions == deletions == cantidad de CRLF). `git add --renormalize --dry-run` lista TODO el repo, no sirve para dimensionar.

- **Kardex es partida doble append-only** — ningún consumidor filtra por status/voided. Anulaciones se reflejan por movimientos compensatorios con `reference: logId`. Historial ruidoso pero contablemente correcto.
